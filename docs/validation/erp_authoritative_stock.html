ERP 현재고를 재고 수량의 기준으로 적용

2026-10-19 · 사용자 확정: ERP 현재고 우선

수불 이력 가져오기와 현재고 보정을 분리합니다. 과거 전표 7건의 상세가 비어 있어도 ERP가 반환한 창고·품번별 현재고로 보정합니다. 빈 전표를 정상 이력으로 처리하거나 삭제하지는 않습니다.

변경 사항

  • sync_erp_history / sync_erp_auto: 이력 오류가 있어도 마지막 현재고 보정을 실행합니다. 이전 전체 동기화 실패 기록도 보정을 막지 않습니다.
  • 이력 오류와 재고 보정 결과를 함께 보존합니다. 재고 보정 성공·이력 오류는 partial 상태이며 명령은 이력 오류를 별도 보고합니다. 이력 전체 성공으로 표시하지 않습니다.
  • ERP 재고 관리의 ‘재고 동기화’ 버튼과 sync_erp_stock 명령은 수불 이력 가져오기를 생략하고 현재고를 직접 보정합니다.
  • MaterialStock.quantity, MaterialTransaction.quantity/result_stock을 Decimal(20,4)로 변경합니다. 기존 정수 데이터는 유지합니다. ERP 수불 가져오기·비교·LOT 보정·재고 화면은 4자리 소수 수량을 보존합니다.
  • ERP가 명시적으로 반환한 0 및 음수도 적용합니다. 음수는 미지정 재고에 반영하고, 지정 LOT의 부족분은 기존 FIFO 방식으로 정리합니다. 변경 수량은 수불에 남깁니다.
  • 기존 일반 입출고 폼의 정수 입력 규칙을 모두 소수 입력으로 바꾸는 작업은 이번 범위가 아닙니다. 기존 입출고 동작과 ERP 소수 재고의 공존을 검증합니다.

기준 데이터가 없는 경우

ERP 조회 실패, 빈 전체 응답, 잘못된 수량은 덮어쓰지 않습니다. 응답에 없는 창고·품번을 임의로 0으로 해석하지 않습니다. 마스터 미등록·동시 변경 항목은 결과에 표시하고 다음 보정에서 재확인합니다. 이는 다른 재고 수치를 우선한다는 뜻이 아니라 적용할 ERP 값이 확인되지 않은 경우입니다.

서버 적용 — 한 줄

cd /var/www/scm_project && git pull --ff-only origin main && bash scripts/deploy_erp_authoritative_stock.sh

기존 운영 서버(root, Linux/systemd, SQLite, venv, gunicorn 서비스)용입니다. 실행 중인 ERP 동기화가 있으면 최대 2시간 기다린 뒤 Gunicorn을 잠시 중지합니다. SQLite 온라인 백업을 /var/backups/scm_project 아래에 생성하고 마이그레이션·DB 구조 점검·정적 파일 수집을 수행합니다. Gunicorn을 다시 시작한 후 ERP 현재고 보정을 실행합니다. API에는 조회만 요청하며 ERP 원본 재고는 변경하지 않습니다.

신규 마이그레이션: material.0061_stock_decimal_quantities. 운영 DB의 마이그레이션 및 재고 보정은 서버에서 위 명령을 실행해야 적용됩니다.

이후 재고만 다시 보정

cd /var/www/scm_project && venv/bin/python manage.py sync_erp_stock --wait-seconds 7200

결과의 adjusted는 보정한 창고·품번 수입니다. error가 있으면 일부 항목만 적용됐을 수 있으므로 skipped_missing / skipped_no_part / skipped_no_wh / skipped_changed 및 메시지를 확인합니다. 실패를 숨기거나 전체 성공으로 처리하지 않습니다.

반복 실행 일정

현재 10분마다 전체 연도 이력을 가져오는 일정은 한 번에 약 50분 걸렸습니다. crontab -e에서 해당 행만 아래 최근 7일 동기화로 교체하고, 전체 연도 점검은 새벽 3시로 분리할 수 있습니다. 기존 2시 과거 변경 감지·23시 성형/MT 집계는 유지합니다. 이 일정 변경은 자동 실행하지 않았습니다.

*/10 * * * * cd /var/www/scm_project && /var/www/scm_project/venv/bin/python -u manage.py sync_erp_auto --days 7 >> /tmp/erp_sync.log 2>&1
0 3 * * * cd /var/www/scm_project && /var/www/scm_project/venv/bin/python -u manage.py sync_erp_history >> /tmp/erp_history.log 2>&1
